# Environment Settings

A program reads and writes the world's environment settings, the ones the
game's environment dialog shows: the time of day, the sky's color, the fog,
the water's height, the ambience.

```
Environment.<environment>.<property>            // read
Environment.<environment>.<property> = value    // write
```

```wirescript
in go: exec
on go {
  let t = Environment.Sky.TimeOfDay
  Environment.Sky.TimeOfDay = t + 1.0
  Environment.Sky.SkyColor = Color(1.0, 0.5, 0.0)
  Environment.Ambience.ReverbEffect = ReverbEffect.LongHallway
}
```

## Reading and writing

- **Exec only.** A read runs the Get Environment Property gate and a write the
  Set Environment Property gate, so both sit on an exec chain: a read outside
  a handler is `WS007`.
- **Names.** An environment is named as the dialog labels it, without spaces
  (`Environment.Ground`), and a property by its name in the game. The editor
  completes both after `Environment.`.
- **Types.** Each property has its own type, listed below, and a write must
  fit it (`WS003`). Colors read and write as `color`.
- **What the game does with a write.** The game converts and clamps a written
  value as the environment dialog would, and leaves a setting the dialog has
  locked alone.
- **Enum properties.** A property backed by a game enum reads as an `int` (the
  member's value) and takes either an `int` or a member of its enum when
  written. The members are listed at the end of this page.
- **Not every property is available.** A property that holds an asset
  reference, an array or a structure with no Wirescript type is listed with
  the reason; reading or writing one is `WS003`.
- **Errors.** An environment or property that does not exist is `WS110`, and
  `Environment.Sky` with no property is an error naming the properties it has.
- **Shadowing.** A binding of the program's own named `Environment` hides the
  builtin.

The list below is generated from the game build the compiler was built
against (`just doc-environment`), so it changes with the game.
